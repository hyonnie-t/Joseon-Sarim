# 사화 시뮬레이션 — 무오·기묘 (v1)

중3 역사 「[9역10-02] 사림 세력의 성장」 수업용 웹앱. history26 포털의 커리큘럼 활동으로 등록해서 쓴다.
설계 근거는 효니가 작성한 핸드오프 문서(`핸드오프_사화시뮬레이션_무오기묘_v1.md`)이며, 이 저장소는 그 문서의
콘텐츠·구조 요구사항을 구현한 것이다.

## 글쓰기①만 먼저 배포하기 (`write1/`)

전체 시뮬(15단계)과 별도로, `write1/index.html` 하나만 지금 바로 배포해서 쓸 수 있다. 로그인 확인 →
카드 분류(사림·훈구) → 카드 두 장 골라 한 마디 쓰기 → 복사해서 Padlet 붙여넣기 → 제출, 4단계만 있는
독립 페이지다(v1.2, 아래 changelog 참고 — 원래는 "비판할래/참을래 + 이유" 구조였다). GitHub Pages로
배포하면 `<Pages 주소>/write1/`로 접근한다.

- `../config.js`(`SHEET_WEBAPP_URL`, `PADLET_BY_BAN`)를 그대로 불러 쓴다 — 백엔드 URL이나 Padlet
  링크가 바뀌면 `config.js` 한 곳만 고치면 이 페이지에도 반영된다.
- `GAME_NAME`은 전체 시뮬과 다른 값(`write1/app.js`의 `WRITE1_GAME_NAME = '사화_글쓰기1_비판할래참을래'`)을
  쓴다 — 커리큘럼에 이 페이지를 별도 활동으로 등록할 때 이 값과 activity id를 맞출 것. 이름은 옛 구조
  때 지어진 것이지만, 이미 포털 커리큘럼에 이 값으로 등록돼 있을 수 있어 진행률·포인트 연결이 끊기지
  않도록 값 자체는 그대로 뒀다(내용만 바뀜).
- localStorage 키는 전체 시뮬과 똑같이 `joseon_sarim_progress_<학번>`을 쓴다. v1.2부터 그 안의
  필드가 `write1_classification`(상자에 담긴 카드, 확정 전 포함)/`write1_locked`(확인 결과 맞아서
  더 못 건드리는 카드, v1.4 추가)/`write1_attempts`(확인 시도 횟수)/`write1_sarim_card`·
  `write1_hoongu_card`(고른 카드 id)/`write1_text`(한 마디)로 바뀌었다 — 옛 `write1_choice`는 더
  이상 쓰지 않는다. **v1.3에서 전체 시뮬(`../app.js`/`../data.js`)의 `write1` 스텝과 회고 화면의
  글쓰기② 프롬프트도 같은 필드 기준으로 맞췄다** — 핸드오프 문서 6장 "열린 질문 1"은 이걸로
  해소됐다(아래 v1.3 changelog 참고). 같은 브라우저로 이 글쓰기①만 하고 나중에 전체 시뮬을 열어도
  (또는 그 반대 순서로 해도) 카드 분류·선택·한 마디가 그대로 이어서 채워진다.
- 이 환경(개발 샌드박스)은 `script.google.com` 자체가 네트워크 정책으로 막혀 있어서 실제 제출까지는
  이 세션에서 못 찍어봤다. 코드 경로는 전체 시뮬의 검증된 제출 로직과 동일하게 맞췄지만, **효니가
  실제 배포 후 학번 하나로 실제 제출까지 한 번 확인해보는 걸 권장**한다.

## 포털 등록 방법

1. history26 교사 대시보드 "커리큘럼 관리" 탭에서 3학년 차시로 새 활동을 추가한다.
2. 활동 URL은 이 저장소를 GitHub Pages로 배포한 주소.
3. **activity id(=이 앱의 `CONFIG.GAME_NAME`)를 `config.js`의 값과 정확히 맞춘다.** 지금은
   `사화_무오기묘_시뮬레이션`으로 임시로 넣어뒀다 — 실제 차시 번호가 정해지면 `config.js`의
   `GAME_NAME` 값도 그 차시 id로 함께 바꿀 것 (예: `12차시_사화_판단시뮬` 같은 형태). 이 값이 안 맞으면
   포털 진행률·포인트 계산에 안 잡힌다.
4. 담당 학년/반: 3학년 5~8반. `config.js`의 `PADLET_BY_BAN`도 이 4개 반만 있다 — 다른 반이 열면
   회고 화면에 "담당 반 정보가 없어서 링크를 못 찾았어" 안내만 뜨고 앱 자체는 끝까지 진행된다.

## 화면 흐름

1. **학번·이름 확인** — 포털에서 `?sid=&name=`으로 넘어온 값을 화면에 띄우고 학생이 직접 확인/수정한다.
   자동 채움만 하고 화면을 건너뛰지 않는다(webapp-builder 스킬 필수 항목 — 값이 안 넘어왔거나 잘못
   넘어왔을 때 학생이 직접 고칠 수 있어야 한다). 5자리 학번 형식 + 이름 입력이 확인돼야 다음으로 넘어간다.
2. **글쓰기 ①** — 이제 이 앱 안에서 실제로 쓴다. 먼저 교과서 123쪽 서술 카드 10장(사림·훈구가
   뒤섞인 순서로 나온다)을 "담지 않은 카드" 더미에서 읽고, 사림 상자 또는 훈구 상자에 실제로
   옮겨 담는다(v1.4 — 버튼을 누르면 그 상자 밑에 카드가 실제로 쌓여서 분류 결과가 바로 눈에
   보인다). 전부 맞아야 다음으로 넘어가며, 틀린 카드는 다시 더미로 돌아가 재분류하면 된다. 그다음
   담은 카드 중 사림 카드 하나·훈구 카드 하나를 골라, "너는 성종 때 3사에서 일하는 관리야"라는
   역할을 먼저 보여준 뒤 그 입장에서 훈구 대신들에게 한 마디(1~2문장)를 쓴다. 다 쓰면 "복사하기"로
   클립보드에 담고 Padlet 링크를 열어 붙여넣는 흐름(webapp-builder 스킬의 "마무리 글쓰기 후 패들렛
   복사 기능"). 사화가 실제로 어떻게 벌어졌는지(결과)는 이 화면에 없다 — 결과를 모른 채 판단해야
   하기 때문. 카드 분류 자체가 사림·훈구 구도를 다루지만, 그건 교과서 123쪽이 이미 정리해 둔
   구도이지 사화의 결과가 아니다.
3. 무오사화 → 전환카드 → 기묘사화 → 전환카드 → 회고, 순서는 핸드오프 문서 6장 그대로.

## 데이터 저장 방식

- **localStorage**: 로그인 확인이 끝난 뒤 `joseon_sarim_progress_<학번>` 키로 진행 상황을 저장한다.
  새로고침해도 이어서 할 수 있고, 회고 화면 재표시에도 이 값을 그대로 쓴다.
- **Google Sheets(history26 백엔드)**: 회고 화면에 처음 도달하면(미리보기 모드 제외) 별도 action 없이
  기존 기본 제출 경로(POST body에 `gameName`만 있으면 게임활동_로그에 1행 기록되는 방식,
  `history26_backend/code.gs`의 `doPost` 기본 분기)로 한 번 제출한다. `choicesJson`에 전체 답변이
  JSON으로 들어가고, `reflection`에는 서술형 답변을 모아 사람이 읽기 좋은 형태로 넣는다. 실패하면
  `fetchJsonRetry`가 3회까지 재시도한다(간격 700ms, history26 관례와 동일). 재시도까지 실패하면
  회고 화면에 "기록 저장에 실패했어. 새로고침해서 다시 시도해봐" 문구만 뜬다(정오 판정이 아니므로
  담담한 문구 유지).
- `?preview=1`로 열면 시트 제출을 하지 않는다(교사 미리보기용). 로그인 확인 화면 자체는 미리보기여도
  그대로 뜬다 — 화면 흐름을 실제와 똑같이 보기 위함.

## 배포 후 수정 (v3.0, 2026-09-28) — 핸드오프 문서 v1 반영: 자동완성 제거·발문 변주·화자 색상·역할 프레이밍 확대

효니가 v2.0 배포본을 "최악이다"로 판정하고, 별도로 의뢰한 제미나이 시안을 참고해 작성한
"핸드오프 문서 v1 — 사화 시뮬레이션(무오·기묘) 재설계"를 그대로 반영했다. `write1/`(글쓰기①)은
이번에도 완전히 무변경 — 다만 이 문서 작성 시점 사이에 다른 세션이 write1을 v1.5~v1.9로 이미
크게 바꿔놨어서(카카오톡식 상소 장면 재구성 등), 그 변경을 먼저 병합하고 나서 작업했다.

- **"내 선택으로 자동완성" 완전 제거** (핸드오프 2번, 확정 사항) — v2.0 회고 화면에 있던 버튼과
  `essayAutoFillText()` 함수를 통째로 삭제했다. 부분 자동완성·초안 제안 등 어떤 형태로도 다시
  넣지 않는다. 서논술문 4단 구성(주장·근거·반론·결론) 자체는 유지하되, `placeholder`에 있던
  모범 예시 문장(=사실상 정답 제공)을 짧고 중립적인 안내("네 생각을 적어봐" 등)로 바꾸고, 대신
  `hint`(기존 💡 힌트 토글과 동일한 패턴)로 "무엇을 떠올려야 하는지" 축만 질문형으로 제시한다.
  결론 문장은 어떤 경로로도 제공하지 않는다.
- **판단 발문 변주** (핸드오프 4번) — 무오·기묘사화 판단 화면에서 반복되던 "당신의 역사적
  선택은?"을 `data.js`의 `judgment.heading`으로 사건마다 다르게 뺐다. 무오사화는 "네가 이 자리에
  있었다면, 어떻게 논의했을까?", 기묘사화는 "대간으로서, 너의 입장은?"(핸드오프 문서가 직접 제안한
  문구 그대로 사용).
- **1인칭 역할 프레이밍 확대** (핸드오프 3번) — 역할 배지(🎭)는 이미 있었지만, `write1`·`m_stage`·
  `k_stage`에만 있고 전환 카드(`t1`/`t2`)에는 없어서 몰입이 끊긴다는 지적을 반영해 `t1`/`t2`에도
  `role` 필드를 추가했다. 구조는 정보 카드 그대로 두고
  시각·프레이밍만 보강하기로 확정(핸드오프 8번 미결정 사항 1·2 — 효니 확인: write1은 그대로,
  3/6·5/6은 판단형 상호작용 추가 없이 시각만). `t1.role`은 무오사화 이후 조정에서 밀려나 상황을
  지켜보는 입장, `t2.role`은 기묘사화 이후 낙향해 서원에서 후학을 가르치는 입장으로 써서 각 전환
  카드의 실제 내용(갑자·중종반정 / 서원·향약)과 자연스럽게 이어지게 했다.
- **화자별 색상 구분** (핸드오프 3번) — 기묘사화 대화(조광조·이성동·중종)가 전부 같은 색 말풍선이라
  구분이 안 된다는 지적을 반영해, `style.css`에 `.avatar.speaker-b`(인디고)·`.avatar.speaker-c`(비취)
  두 클래스를 새로 추가하고 `app.js`의 채팅 렌더러가 화자 등장 순서대로 배정한다. **⚠️ write1이
  공유하는 `.avatar`(기본)·`.avatar.royal` 규칙은 전혀 건드리지 않았다** — write1의 카카오톡식 상소
  장면(v1.8)도 같은 `.avatar`/`.avatar.royal`을 쓰고 있어서, 여기 손을 대면 write1까지 영향을 준다.
- **진행바에 사건명 노출** (핸드오프 3번) — "숫자만 보이고 사건명이 안 보인다"는 지적을 반영해
  `index.html`에 `#stageDots` 스테퍼를 추가하고(`data.js`의 `navLabel` 필드 사용: 글쓰기① · 무오사화 ·
  갑자·중종 · 기묘사화 · 을사·향촌 · 글쓰기②), 진행 중인 단계를 강조 표시한다. 클릭으로 건너뛰는
  기능은 없다(순서를 강제하는 기존 원칙 유지) — 읽기 전용 표시.
- **사실 검증** (핸드오프 6번) — 조의제문 발췌문, 처벌 논의(정문형 등의 의견이 실제로 채택됐다는
  것은 "從文炯等議" 원문으로 재확인), 이유청 등 형장 30대, 이성동(李成童) 인명, 위훈삭제 판결문
  인용까지 WebFetch로 sillok.history.go.kr 원문을 다시 대조했다 — 전부 기존 서술과 일치해서
  내용은 그대로 유지했다(이전 세션의 "verified:true" 표기를 그대로 믿지 않고 원문을 다시 확인).
- **CSS 작업 방식 변경**: v2.0 때 `style.css`를 통째로 다시 쓰면서 write1이 그 사이 추가한 새
  클래스(`.pick-chip` 등)를 덮어쓸 뻔한 사고가 있었다(그때는 `main`과의 병합으로 복구). 이번에는
  같은 실수를 막기 위해 `style.css`를 전체 재작성하지 않고 필요한 부분만 `Edit`로 추가했다.

## 배포 후 수정 (v2.0, 2026-09-28) — 전체 시뮬 UI/구조를 참고 디자인 기준으로 재구성 (`write1/`은 무변경)

효니가 제미나이로 만든 참고 웹앱("사화의 폭풍" — 무오→전환카드→기묘→전환카드→글쓰기 조합기, 5단계
카드뉴스형 구성)을 훨씬 낫다고 판단해서, 그 구조·시각 디자인을 기준으로 전체 시뮬(`index.html`/
